## 配置怎么定：4 核 8G 能开，4 核 16G 才舒服

官方文档给出的服务器配置要求是最低 4 核 8G、推荐 4 核 16G，多人或大建筑量建议 32G 以上。这个数字不是拍脑袋，幻兽帕鲁服务端要同时跑地图实体、帕鲁 AI 和大量建筑数据，内存是第一个瓶颈。

实际玩家反馈的分档大致是这样：4 核 8G 开五个以内的好友局够用，跑久了内存会有压力；4 核 16G 撑十个人左右明显更稳；16G 以上、人多建筑多才谈得上宽裕。

带宽是另一回事，官方没有给标准，第三方实测的经验值可以参考：

| 带宽 | 可支持人数 |
| --- | --- |
| 5M–7M | 4–6 人 |
| 10M–15M | 7–12 人 |
| 15M–30M | 13–30 人 |

这组数字来自第三方实机测试，不是官方口径，但方向是对的：人数上去了，带宽比 CPU 更容易先撑不住。

还有一个绕不开的问题：幻兽帕鲁服务端存在内存泄漏，跑久了内存占用会一路往上涨，最后卡顿甚至崩服。8G 的机器建议额外配 8–12G 的 SWAP 当缓冲，再配一个内存占用超过 90% 自动重启服务端的脚本，回档大约十秒，玩家基本感觉不到。想从根上解决还是加内存，SWAP 只能救急。

## Linux 开服：从 SteamCMD 到进服

自己装的话，整套流程就四步。

**第一步，放行端口。** 幻兽帕鲁服务端默认走 **UDP 8211**，必须在防火墙或安全组里放行这个端口，协议选 UDP，别选成 TCP。用面板服的话不用管这步，在控制台做 NAT 端口映射到 8211 就行。

**第二步，装 SteamCMD 拉服务端。** 在 Linux 上装好 SteamCMD 后执行：

bash
steamcmd +login anonymous +app_update 2394010 validate +quit


`2394010` 是幻兽帕鲁专用服务端的 app id，`validate` 会校验文件完整性，第一次装可能要等几分钟。

**第三步，启动服务端。** 进入安装目录执行启动脚本。想让它在 SSH 断开后继续跑，用 tmux 或 screen 挂着，或者写成 systemd 服务托管，服务器重启后能自动起来。Windows 侧的启动命令是 `PalServer.exe port=8211`，进程名 `PalServer-Win64-Test-Cmd.exe` 出现就说明起来了。

**第四步，进服。** 游戏里点「加入多人游戏（专用服务器）」，在底部输入 `服务器IP:8211`，有密码的话填密码，点连接。

连不上先查三件事：端口协议是不是 UDP、安全组规则有没有真正生效、服务端进程是否还活着。

## 配置文件：改错文件等于白改

这一节是 Linux 服最容易翻车的地方，值得单独讲。

配置文件的正确路径是：


pal/Pal/Saved/Config/LinuxServer/PalWorldSettings.ini


默认模板在同级的 `pal/DefaultPalWorldSettings.ini`。**模板文件改了不生效**，`PalWorldSettings.ini` 新建出来又是空的。正确做法是把 `DefaultPalWorldSettings.ini` 里的内容整段复制进 `PalWorldSettings.ini`，再在后者里改参数。直接改模板，或者自己手打一份参数列表，多半没效果。改完保存，重启实例才生效。

几个常改的参数和官方默认值：

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `ServerPlayerMaxNum` | 32 | 服务器玩家上限 |
| `GuildPlayerMaxNum` | 20 | 公会人数上限 |
| `BaseCampWorkerMaxNum` | 15 | 单个据点工人上限 |
| `DeathPenalty` | All | 死亡惩罚，可选 None / Item / ItemAndEquipment / All |
| `ExpRate` | 1.000000 | 经验倍率 |
| `PalCaptureRate` | 1.000000 | 捕捉概率倍率 |
| `PalEggDefaultHatchingTime` | 72.000000 | 蛋默认孵化时间（小时） |
| `PublicPort` | 8211 | 公共端口 |

死亡惩罚改成 `None` 是不掉落，`Item` 只掉物品不掉装备，`ItemAndEquipment` 掉物品和装备，`All` 全掉。三五好友的私服一般直接改成 `None`，省得每次捡尸。蛋孵化 72 小时对休闲局太长了，改成 1–6 小时很常见。经验倍率看你们想玩多久，2–3 倍能明显缩短前期。

服务器名称、服务器密码、管理员密码也在同一个文件里，`ServerName`、`ServerPassword`、`AdminPassword` 三项建议都填上，尤其是开公开服的时候。

面板服改配置的路径完全一样，只是用面板自带的文件管理器点进去编辑，不用 SSH。改完一样要重启实例。

## 存档迁移：一个目录名决定能不能读出来

服务端存档在 `PalServer/Pal/Saved` 下面，主要涉及 `config` 和 `savedgames` 两个文件夹。迁移前有两件事必须做：停服、备份。带着运行中的服务端搬存档，损坏的概率不低。

**Windows 和 Linux 之间互转**，问题出在 `config` 里的目录名上。Windows 服务端读的是 `WindowsServer`，Linux 和面板服读的是 `LinuxServer`。把存档搬到另一种系统上，要进 `config` 文件夹把目录名改成目标系统认识的那个，否则服务端起得来，存档读不出来。除此之外就是删掉目标机器的 `config` 和 `savedgames`，把备份解压进去。

**本地或合作模式存档转到专用服务器**，多一步。合作模式的存档会绑定房主的角色文件，直接扔进服务器会出现"每个玩家都要重新建角色"的问题。需要借第三方脚本 `xNul/palworld-host-save-fix` 配合 `uesave` 和 Python 跑一遍转换，命令大致是：

bash
python fix-host-save.py ...\uesave.exe ...\SaveGames\0\8A15... EE256A5000000000000000000000000


最后那个参数是玩家 .sav 文件名去掉扩展名。如果是云主机或面板服，脚本没法在服务器上跑，得先用 FTP 把存档下载到本地、在本地跑完脚本、再传回去覆盖。这一步很多人卡住，其实就是脚本依赖本地 Python 环境。

## 日常运维：内存、备份、可视化

**内存监控**。前面提过的内存泄漏是长期服的主要故障来源。8G 机器加 8–12G SWAP，配一个内存占用超过 90% 自动重启服务端的脚本，是目前成本最低的方案。16G 以上能明显延缓，但不代表不会发生。

**自动备份**。存档目录整个打包就行，`PalServer/Pal/Saved` 下面全部内容。开公开服的话，备份频率建议不低于每两小时一次，炸服、误删据点、玩家冲突都用得上。

**可视化管理**。有个第三方工具 `palworld-server-tool-enhanced`，基于 .sav 解析和 REST&RCON，能看服务器总览、玩家列表、地图、帕鲁、据点、库存、配种农场，也能直接在界面上改世界设置和做运维操作，桌面端和移动端都能用。不想天天敲命令的话值得装一个。
